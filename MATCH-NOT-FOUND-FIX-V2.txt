NPLcode Match Not Found Fix v2

Deploy the ENTIRE project ZIP, not only detail.html.

What changed:
- The match page reads matches/{Firebase key} from the configured Realtime Database.
- If the URL uses a match alias (id, matchId, slug, match_id, key), it searches the matches collection.
- A valid match is no longer rejected just because startTime is missing or stored as a date string.
- Team metadata is optional; a failed teams read will not make a valid match appear missing.
- The /api/match route is marked no-store to prevent stale cached HTML.

Database configuration:
- Realtime Database URL is currently:
  https://ramus-7f7aa-default-rtdb.firebaseio.com
- Expected data paths:
  /matches/{matchKey}
  /teams/{teamKey}
- Public read access (or a properly authenticated server-side read) is required for browser REST reads.

Important diagnosis:
If the page still says "No match record exists for ID", the final path segment in /match/{ID}
does not match any key under /matches and does not match any alias field in that record.
Open Firebase Realtime Database -> matches and use the exact child key in the URL.
If it says "Could not contact the match database", check database URL, read rules, and browser network errors.
