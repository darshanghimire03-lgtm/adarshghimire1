Windows Hands-On Labs

Every lab runs on a Windows VM you build and own. No real targets.

Lab 1 — Windows Local Account Recovery (Owned VM)

Goal

Understand what a physical attacker can do to an unprotected Windows machine — and how to stop them.

Setup

  1. Install Windows 10 or 11 in VirtualBox or VMware.
  2. Create a local test account with a password you control (not a Microsoft account).
  3. Take a snapshot so you can restore the VM at any time.

Exercise

  1. Boot your VM from the Windows installation ISO.
  2. Choose Repair your computer → Troubleshoot → Command Prompt.
  3. Examine your own VM's SAM and SYSTEM hives.
  4. Try the classic utilman.exe swap technique on your VM only.
  5. Restore the snapshot afterward.

Report (required)

  1. Which method worked on your unprotected VM?
  2. Which single Windows setting would have blocked it?
  3. Write the hardening checklist you'd give a small business owner.
⚠ Only on a VM YOU own. Performing this on any other Windows machine — even one you can physically touch — is a criminal offense under CFAA and equivalent laws worldwide.

Lab 2 — SAM Hash Extraction & Offline Analysis

Setup

  1. On your VM, create three local accounts: user_weak (password: Password1), user_medium (Summer2024!), user_strong (16-char random).
  2. Snapshot the VM.
  3. Extract the SAM and SYSTEM hives to your analysis host (your own machine).

Analysis

  1. Use secretsdump.py or samdump2 on the copied hives.
  2. Run hashcat -m 1000 hashes.txt rockyou.txt.
  3. Record crack time for each account.
  4. Graph the relationship between password entropy and crack time.
✔ Conclusion you're aiming for: password length and entropy dominate — a 16-character random password is effectively uncrackable with consumer hardware.

Lab 3 — Microsoft Account Password Reset (Legitimate Path)

Goal

Learn the official recovery flow Microsoft provides — the one you'd walk a real user through.

  1. Create a test Microsoft account.
  2. On the VM, sign in with it and enable "Sign in with Windows Hello."
  3. Boot a separate browser → account.live.com/password/reset.
  4. Complete the reset with your recovery email.
  5. Sign back into the VM with the new password.
  6. Document why this path is safe and the local-account path isn't.

Lab 4 — Windows Event Log Forensics

Goal

Detect a password attack from the defender's side.

  1. Enable Audit Logon Events and Audit Account Logon Events in secpol.msc.
  2. From a second VM, attempt several failed RDP logins against your target VM.
  3. Open Event Viewer → Windows Logs → Security.
  4. Find Event ID 4625 (failed logon) and 4624 (successful).
  5. Write a Splunk/PowerShell query that would alert on 10+ failed logins in 60 seconds.
✔ This is the skill employers actually pay for: not breaking in, but spotting when someone tried.

Windows Hardening Checklist

Every lab ends with these defenses. Teach offense to teach defense.

BitLocker + TPM

Full-disk encryption with TPM 2.0 + PIN blocks offline SAM extraction completely.

Windows LAPS

Randomizes local admin passwords per machine, rotated automatically.

Credential Guard

Isolates LSASS in a virtualization container — defeats most credential dumping.

BIOS / UEFI Password

Stops boot-from-USB attacks before Windows even loads.

Microsoft Account + Hello

Cloud-backed recovery + biometric login removes the local-password attack surface.

Account Lockout Policy

5 attempts → 15 min lockout neutralizes brute-force RDP attacks.
